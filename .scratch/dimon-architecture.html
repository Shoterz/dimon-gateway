Inference gateway — services/inference_gateway

uv run dimon-inference-gateway · 127.0.0.1:8891 (GPU host only)

Cloudflare Tunnel + Access · published as dimon-inference.stocksuite.app · auth, per-identity rate limits, idempotency, queueing, content-free observability

A locked front door to the GPU host. It checks who you are, then forwards only a narrow, pre-approved question to the models — never a raw connection to them.

One request, start to finish

The exact case the test suite calls the "golden request." Every payload below is a real shape from the code — the model's IDs, timestamps, and digests are generated at request time, so those specific values are illustrative.

1

Browser → App

Someone types or says a request

The UI sends the raw sentence to the backend. Nothing has been interpreted yet.

POST /api/actions

{
  "request_id": "00000000-0000-4000-8000-000000000020",
  "text": "Send John Smith S$50 from savings."
}
2

App → Qwen (or fixture)

The model proposes what it thinks the sentence means

The app sends the sentence to Qwen with a fixed instruction: extract fields, invent nothing, quote your evidence, return only JSON matching this exact shape. This is a proposal, not a decision — the app still checks every field itself in the next step.

Qwen's structured reply

{
  "kind": "BENEFICIARY_TRANSFER",
  "source_account_ref": "savings",
  "source_evidence": "savings",
  "recipient_label": "John Smith",
  "recipient_evidence": "John Smith",
  "currency": "SGD",
  "payment_reference": null,
  "reference_evidence": null
}

Note: Qwen never returns the amount. Deterministic Python re-derives "S$50" → 5000 cents straight from the original sentence, so the model can't misstate money.

3

Inside the app — deterministic Python

The app grounds and checks every claim itself

Plain Python — no model involved — looks up "John Smith" in the saved beneficiary list, confirms "savings" is a real account, parses the amount from the sentence text, and refuses to continue if anything doesn't match exactly.

what got checked

recipient_label "John Smith"  → matches saved beneficiary bnf_john_smith_01
source_account_ref "savings" → matches account acct_savings_01
"S$50" in original text      → amount_minor = 5000, currency SGD
evidence strings              → exact substrings of the user's sentence, not invented
4

Inside the app

A receipt is written — but nothing has moved yet

Before touching the ledger, the app writes down exactly what it's about to do and fingerprints that statement. The person has to approve this exact fingerprint next — if even one digit changed, the fingerprint would too.

stored receipt (status: AWAITING_CONFIRMATION)

{
  "receipt_id": "rcpt_...",
  "status": "AWAITING_CONFIRMATION",
  "amount_minor": 5000,
  "currency": "SGD",
  "recipient_display_name": "John Smith",
  "source_account_id": "acct_savings_01",
  "receipt_digest": "sha256 of the fields above",
  "expires_at": "created_at + 5 minutes"
}
5

Browser → App

The person approves that exact receipt

The browser shows the locked facts and sends back the receipt's own fingerprint as proof the person saw the same thing the server did. A mismatched or reused fingerprint is rejected — no debit happens.

POST /api/receipts/rcpt_.../approve

{ "receipt_digest": "sha256 of the fields above" }
6

Inside the app — SQLite ledger

Money actually moves, exactly once

The app writes one ledger transaction and two ledger entries (debit savings, credit John Smith), guarded so replaying the same request never double-spends.

response

{
  "outcome": "EXECUTED_SYNTHETIC_TRANSFER",
  "state": {
    "accounts": [
      { "account_id": "acct_savings_01", "balance_minor": 95000 }
    ]
  }
}
7

App → Kokoro → Browser

The result is spoken back

The app builds one fixed sentence from the committed result — never free text — and Kokoro turns only that sentence into audio.

text sent to Kokoro, and what the person hears

"Synthetic transfer complete. 50 dollars and 00 cents moved to John Smith."

Qwen (intent)

GPU host

Pinned GGUF served by an externally installed llama-server, 1 slot, 16K context. Called with an OpenAI-shaped /chat/completions request built in model_adapter.py, with a strict JSON schema forcing structured output — the model can only propose, never execute.

GPU host

NVIDIA NeMo-Speech.cpp v0.1.0 streaming server. NemotronClient opens a WebSocket, sends 16 kHz mono PCM16 frames, receives partial/final transcripts.

GPU host

Repository-owned minimal FastAPI service (not the upstream Kokoro server) exposing only bounded synthesis + health routes. Speaks committed results only — never arbitrary text.
